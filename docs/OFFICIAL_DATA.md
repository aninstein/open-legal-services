# 官方数据接入与展示边界

## 每日更新

服务运行时的后台任务按 UTC 日期对 `law`、`exam`、`case` 三个来源各执行一次。每天首轮检查大约在启动 5 秒后运行；之后每小时检查漏跑情况。`sync_runs` 记录成功、失败、扫描条数和错误；`official_updates` 以官方 URL 去重。管理员可在后台点击“立即检查更新”，也可运行 `legal-service sync-sources --force`。部署多个 API 实例时应使用单独的调度进程或分布式锁；当前单实例配置适合本地和单容器运行。

| 分类 | 当前采集范围 | 未采集内容 |
| --- | --- | --- |
| 法规政策 | 中国政府网政策发布页中匹配法律、条例等标题的链接 | 条文全文、修订关系、效力状态 |
| 法考 | 司法部法律职业资格管理局页面上的考试公告链接 | 真题正文、参考答案、AI 生成题 |
| 公开案例 | 最高人民法院典型案例发布目录的标题链接 | 案情全文、裁判文书、当事人身份 |

“收录日期”只是平台获取链接的日期，不是发布或施行日期；从 URL 能识别出的年月标为“来源月份”。页面不会据此推断法律现行有效。案例是学习参考材料，具体案件应核对原站内容、法院、裁判日期、案号及匿名处理情况。

## 企业登记信息

国家企业信用信息公示系统是公开登记、股东和出资信息的官方入口。完整查询可能需要实名用户，当前网络环境访问该站也会触发网站防护。平台尚无正式授权的服务端数据接口，因此企业搜索 API 返回 `official_login_required`、空结果及官方入口；这表明尚未取得平台内结果，不代表企业不存在。不要以非官方抓取结果冒充权威登记记录。

要实现平台内的结构化企业结果，需要取得官方或获授权数据提供方的接口许可，记录来源、查询时间、统一社会信用代码、登记状态、经营范围、股东与认缴信息及字段级更新时间，再设计权限、缓存和纠错流程。未经许可，不应绕过实名登录、验证码或访问限制。

## 律师认证资料

申请人提交真实姓名、性别（可选）、联系电话、身份证号、职业头像、身份证两面、律所、至多五项业务领域、执业证首页及备案页、执业证号、注册地区、开始执业日期和个人简介；荣誉、社交链接、匿名案例摘要可选。管理员需查看图片并核对执业信息来源后才能通过。身份证、证件图片只允许申请人本人和管理员读取，查看行为留审计日志；职业头像仅在认证通过后公开。生产环境应使用 HTTPS、加密备份和明确的数据保留/删除制度。
